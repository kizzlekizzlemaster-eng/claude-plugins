# 뉴트랩 보고서 양식

보고서·기획안·제안서·현황 정리를 쓸 때 이 순서로 한다. 회의록과 회사 명의 대외 문서(계약·통지·증명)는 각자 기준이 따로 있다.

## 1. 종류를 고른다

| 종류 | 언제 | 길이 | 템플릿 |
|---|---|---|---|
| 원페이지 기획 | 짧은 기획·제안·결정 요청 | A4 1장 | `templates/원페이지-기획.md` |
| 보고서 | 분석·현황·결과·조사 | A4 2~6장 | `templates/보고서.md` |

## 2. 템플릿을 복사해 쓴다

- 파일 이름은 `docs/YYMMDD-제목.md`. 같은 이름이 이미 있으면 제목을 바꾼다.
- 머리말(---)은 그대로 둔다. 원페이지는 `인쇄: 원페이지`, 표가 많은 보고서는 `인쇄: 조밀표`를 넣는다.
- 첫 섹션은 반드시 「결론」이다. 템플릿의 섹션 순서를 바꾸지 않는다.

## 3. 문체 규칙을 지킨다

`rules.md`의 17개 규칙을 그대로 따른다. 핵심은 열이다.

- 쓰기 전에 네 줄: 읽는 사람의 질문 · 답 한 문장 · 이유 묶음 2~4 · 다루지 않는 것 (`structure.md` 2절). 못 적으면 아직 쓸 때가 아니다.
- 구조는 문제 → 원인 → 해결 → 결정. 자료(현황 · 지표 · 사례 · 일정)는 장이 아니라 근거다. 뼈대 셋은 `structure.md`.
- 제목은 주장문. "지금 숫자"가 아니라 "주문당 광고비가 3.5배가 됐다".
- 결론 먼저. 근거는 뒤에. 긴 결론은 「지금 상태 · 바꾸는 것 · 정할 것」 묶음 불릿으로.
- 두 장 넘으면 결론 앞에 「이 문서는 왜 썼고, 어떻게 읽나」 — 왜 썼나 · 요지 세 줄 · 목표 · 누가 어떻게 읽나 표(결정하는 사람 · 판단하는 사람을 이름으로).
- 한 문장 20단어 안쪽, 문장 하나에 뜻 하나.
- 같은 대상은 끝까지 같은 이름.
- 숫자가 나오면 맨 앞에 용어 설명표(용어 · 쉬운 말 · 지금 값).
- 모르는 단어 0. 읽는 사람 열에 여덟이 모를 용어·약자는 처음 나올 때 풀거나 표에 넣는다.
- 강조 두 가지. 판단·결정은 **굵게**, 꼭 기억할 숫자·한 줄은 `<mark>형광</mark>`. 섹션당 형광 셋 안쪽.
- 도식화. 흐름·구조·분기·일정·2축 비교가 글로 세 문장을 넘으면 ```mermaid 그림으로 바꾼다. 규칙·본보기는 `diagrams.md`를 읽고 쓴다.

## 4. 쓰고 나서 검사한다

1. 첫 섹션이 「결론」인가. 결론 3줄 안에 무엇·왜·언제가 있는가. 「왜 썼나」 첫 문단에 상황 · 문제 · 답(SCQA)이 있는가.
1-1. 제목만 이어 읽어 문제 → 원인 → 해결 → 결정 줄거리가 보이는가. 주제 제목("현황", "지표", "분석")이 하나라도 있으면 주장문으로 고친다. 자료만 있는 장은 부록으로.
2. 같은 대상을 다른 이름으로 부른 곳이 없는가. 문서 안에서 핵심 용어를 찾아 하나로 맞춘다.
3. 상투구가 없는가. 아래 한 줄로 찾는다.
   ```
   grep -nE "결론적으로|요약하면|정리하자면|시사하는 바|크게 .* 가지|다음과 같|할 때입니다|시점입니다" <파일.md>
   ```
4. 설명 없이 쓴 전문용어·약자가 없는가. 영어 약자를 모두 뽑아 용어 설명표와 대조한다.
   ```
   grep -oE "\b[A-Z][A-Za-z+]{1,}\b" <파일.md> | sort | uniq -c | sort -rn
   ```
   표에 없는 약자는 표에 넣거나 본문에서 쉬운 말로 바꾼다. 사내 은어(판·오프·데뷔 등)도 같다.
5. 두 장 넘는 문서면 「이 문서는 왜 썼고, 어떻게 읽나」가 있고, 「누가 어떻게 읽나」 표에 결정하는 사람 이름이 있는가.
6. 글로 남은 흐름·구조·분기·일정이 없는가. 있으면 `diagrams.md`대로 그림으로 바꾼다. 변환기 출력에 "문법이 틀려 그리지 못했습니다"가 없어야 한다.
7. 강조가 있는가. 결론과 각 장에 굵게·형광이 하나도 없으면 어디를 볼지 정해서 넣는다. `grep -c '<mark>' <파일.md>`가 0이면 안 된다.
8. 한글 AI 티 검사 스킬(`/humanize-korean`)이 있으면 돌린다.

## 5. PDF를 만든다

```
python3 <스크립트> <파일.md>
```

- 스크립트 위치: ERP 저장소에서는 `scripts/md_to_a4_pdf.py`, 플러그인으로 설치한 폴더에서는 `${CLAUDE_PLUGIN_ROOT}/scripts/md_to_a4_pdf.py`.
- PDF는 현재 폴더의 `pdf/`에 생긴다. docs 폴더에 PDF를 두지 않는다.
- 스크립트가 쪽수와 도식 수를 출력한다. 원페이지인데 2쪽이면 줄여서 다시 만든다.
- ```mermaid 블록은 변환기가 그림으로 그린다(플러그인에 mermaid가 들어 있어 인터넷 불필요). ERP 위키 화면도 같은 그림을 그린다.
- 처음 한 번은 `pip3 install markdown`이 필요하다. 크롬이 설치돼 있어야 한다.

## 6. 제출한다

- 직원: ERP 보고서함(`/reports/docs`)에 MD와 PDF를 올린다. 회의에서 다룰 보고서는 그 회의 일정의 「안건」으로 올린다.
- ERP 저장소에서 쓴 보고서: `docs/`에 두고 해당 지식맵에 링크 한 줄을 넣는다. 그다음 `node scripts/check-knowledge-links.mjs`를 돌린다.
- 원가·급여·자금이 들어간 문서는 경영진 전용이다. 위키에 올리지 않는다.
